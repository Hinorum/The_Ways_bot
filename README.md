# The Ways — LOST HOWL

Фанатский Telegram-бот по мотивам Lost Dogs: The Way — не связан с официальной командой, использует только общие мотивы и собственные имена.

Бот — это **видеомагнитофон LOST HOWL** в Telegram: раз в месяц Хранитель ставит в лоток **кассету** — рукописный фанфик-продолжение (стая псов ищет дом в разрушенном городе). Каждый день игроки выбирают **один из трёх черновиков кадра** кнопкой под постом дня; закон дня (большинство / меньшинство / середина) честной энтропией решает, какой кадр уцелеет и напишет канон дня. Поверх сюжета — **блокчейн-экономика** (Gram, бывший TON): исход дня решают банки ставок, бесплатные голоса ведут лидерборд, а верные пути копят Следы и копилки. Вся механика заточена под честный подсчёт, выплаты и копилки; внешних платных API нет.

## LOST HOWL — что это

**Стая** — игровое сообщество бота. У бота нет своего мира: он плеер, а сценарий — кассеты-фанфики, которые пишет и ставит в лоток **Хранитель** (месяц = кассета, файлы в `app/story/cassettes/`). Плёнка нарезана на кадры: заголовок главы, живая сцена (текст дня) и развилка из трёх черновиков кадра. Кассета умеет «перематываться»: если в день `D` уцелел определённый кадр, с дня `D+1` и до конца месяца играется ответвление сюжета; невыбранные кадры в сценарий больше не возвращаются. Канон дня (что именно произошло) звучит в итогах адресно победившим кадром. За миром следит **Хранитель**: ведёт казну, разбирает споры, держит стоп-кран, выбирает кассету месяца.

## Как устроен день

Сутки Стаи заякорены на UTC (по умолчанию день открывается в 11:00 UTC, голосование закрывается в 11:00 UTC следующего дня):

1. **Открытие дня** — пост: заголовок главы, живая сцена кассеты (текст дня) и развилка из трёх черновиков кадра (`Путь I/II/III` — название и короткое описание каждого). Закон дня объявлен сразу, банки ставок скрыты. Выбор — кнопкой под постом или кнопками пульта.
2. **Выбор пути** — один голос на игрока в сутки (`INSERT` с уникальностью `(round_id, player_id)`). Бесплатный голос ведёт лидерборд игрока, но на исход дня не влияет: решающий счёт — суммы подтверждённых ставок Gram на каждом пути.
3. **Закрытие и подсчёт** — мгновенный: `SUM(ставок) GROUP BY card_position`, побеждает путь по закону дня. День, на который не поставлено ни одного Gram, решается голосами.
4. **Итоги и новый день** — приходят в чаты сразу: канон дня (текст уцелевшего кадра), голоса, очки и выплаты; при «перемотке» кассеты с нового дня играется ответвление сюжета. Тяжёлая часть (выплаты, копилки) уходит фоном.

Три закона дня применяются к **банкам путей**: **большинство** (побеждает путь с большим весом ставок), **меньшинство** (с меньшим), **медиана** (средний по счёту). Закон дня выводится из **энтропии мастерчейна** — `root_hash % 3` последнего блока TON в момент открытия дня (как жребий при ничьей): блок в цепочке до начала голосования, подогнать закон задним числом нельзя (номер блока и `root_hash` хранятся в записи дня и доступны хранителю; в сообщения игроков они не печатаются). Закон **публичен с первой минуты** — никаких скрытых правил: игроки делают выбор, зная, что сегодня решает. В день без ставок те же законы применяются к бесплатным голосам.

### Проверка закона дня

Закон объявляется публично в анонсе дня — скрытых правил нет. Блок-источник и его root_hash хранятся в записи дня (колонка `rule_entropy`, формат `seqno:root_hash`) и доступны хранителю; в сообщениях игроков они не печатаются. Проверка занимает пару минут:

1. Узнай у хранителя (или из БД) номер блока и `root_hash` — 64 hex-символа.
2. Открой страницу блока в эксплорере, например `https://tonviewer.com/block/-1:8000000000000000:85601844`, и сверь поле **Root hash**.
3. Посчитай `root_hash % 3` (0 = большинство, 1 = меньшинство, 2 = медиана):
   ```python
   int("…root_hash…", 16) % 3
   ```
4. Сверь результат с законом дня — они должны совпасть дословно. Блок запаян валидаторами и лежит в цепочке до открытия дня, поэтому его хеш нельзя подогнать под голосование задним числом.

Вручную день можно закрыть раньше командой `/advance` (только админы из `ADMIN_IDS`). Стейки и выплаты — по UTC-сетке, без привязки к онлайн-статусу бота.

## Экономика дня (Gram = бывший TON)

Игра бесплатна; ставки включаются флагом `TON_ENABLED=true`. Игрок привязывает кошелёк (`/wallet`) и в течение дня переводит **нативную монету Gram** на казначейский кошелёк — это и есть ставка на выбранный путь.

- Одна ставка на игрока в день, минимум `STAKE_MIN_TON` (по умолчанию 0.5 Gram), верхней границы нет. Перевод токенов (USDt, NOT и пр.) ставкой не становится — watcher пропускает jetton-уведомления.
- Watcher раз в минуту читает входящие транзакции казначея через **TonAPI** (фолбэк — **Toncenter** при деградации), курсор хранится в БД: простой сервиса не теряет переводы, хвост догоняется за пару циклов. Ставка подтверждается по отправителю, поэтому форма адреса (UQ/EQ) и memo не важны.
- Исход дня по ставкам включается флагом `WINNER_BY_STAKES=true` (по умолчанию): закон дня применяется к суммам Gram, путь без ставки участвует как 0 Gram. При `false` возвращается прежний исход по голосам и снова работают легаси-рычаги `STAKE_VOTE_BONUS_WEIGHT` / `WIN_RULE_PREFERS_STAKED`.
- Фонд дня = сумма подтверждённых ставок. Если на победивший путь кто-то поставил:
  - **96%** — поставившим на верный путь, пропорционально ставкам (комиссия сети вычитается заранее, приз приходит «чистыми»). Если кто-то из поставивших пришёл по личной ссылке игрока (механика `/invite`, `REFERRAL_SECRET`), с таких ставок ещё **1%** уходит в копилку пригласившего, а не в пул победителей — доля победителей того дня падает (в пределе до ~95%);
  - **1%** — в Фонд Стаи (`PACK_FUND_PCT`, накопление, раздача вручную);
  - **2%** — в копилку недели (в понедельник её делят топ-3 недели);
  - **0,5%** — хранителю (`OWNER_RAKE_PCT`);
  - **0,5%** — в копилку месяца (1-го числа топ-3 месяца).
- Если на победивший путь не поставил никто — все ставки возвращаются игрокам без рейка и копилок (с вычетом газа сети). Отклонённые лимитами, неподтверждённые и «чужие» переводы попадают в очередь авто-возврата — деньги не оседают в казне молча.
- Мелкие доли (< `MIN_PAYOUT_GRAM`) не превращаются в дохлые переводы — капают в копилку недели. Идемпотентность по хешу транзакции и мемо защищают от задвоения выплат; статус «взята в работу» фиксируется до вещания — падение сервиса не ведёт к двойной оплате.

### Блокчейн-контур выплат

- **Диспетчер** раздаёт призы и возвраты: батч на ОДНОМ `get_seqno()` (два подряд перевода не получают одинаковый seqno — иначе один молча теряется), идемпотентность по memo комментарию.
- **Глубокая сверка истории казначея**: memo исходящих читается не одной страницей (128 tx), а страницами вглубь (до `PAYOUT_RECONCILE_MAX_PAGES`, окно `PAYOUT_RECONCILE_HISTORY_SECONDS` ≈ неделя, шаг с перекрытием 16 записей — memo на стыке страниц не теряется). TonAPI → фолбэк Toncenter.
- **Сверка «по требованию»**: когда сверять нужно конкретные memo (sent-выплаты без реального хеша), пагинация останавливается сразу после нахождения всех целей — слепого прохода до конца окна нет, меньше запросов к провайдеру.
- **Анти-дубль повтора**: повтор выплаты с `attempts > 1` при НЕдоступной истории замораживается — переотправка без возможности проверить memo = риск задвоить уже ушедший перевод. «Провайдеры молчат» и «переводов нет вообще» различимы.
- **Сверка «sent»** каждые 120с: memo из истории пишутся как реальный хеш; memo без подтверждения после `PAYOUT_CONFIRM_TIMEOUT_SECONDS` (20 мин) возвращаются в очередь — потерянный при гонке двух быстрых переводов приз переотправляется сам.
- **Общий HTTP-клиент** с пулом keep-alive соединений между циклами watcher/диспетчера и экспоненциальный backoff ретраев; «мёртвые» входящие ротируются по `STUCK_RETENTION_DAYS`.
- `/blockchain` — аудит-отчёт блокчейн-контура для разбора «куда делось»: история казначея, сверщики, наши исходящие, стuck-входящие.

### Смена выбора — платно

Один голос в день, но передумать можно за **Telegram Stars** или **Gram** с memo (`/change` в личке, `REVOTE_STARS` / `REVOTE_TON`). Грант сгорает вместе с днём.

### Копилки недели и месяца

Каждый день 2% фонда капает в копилку недели: в понедельник её делят **топ-3** прошедшей недели по числу верных путей (совпадений голоса игрока с победившей тропой) 50/30/20. Копилку месяца (0,5% в день) топ-3 забирают 1-го числа. Для призового места нужен привязанный кошелёк и минимум `WEEKLY_MIN_DAYS` дней голосования за период (анти-мультиаккаунт). Доля без достойного игрока переносится в следующий период. Живые таблицы — в `/top`.

## Команды игрока

- `/start`, `/help` — онбординг и памятка (с «пультом» кнопками)
- `/menu` — пульт LOST HOWL: сегодня, счёт, место, кошелёк, ставка, копилки, фонд, обновления — всё по кнопкам
- `/today` — кадр дня: глава кассеты живым текстом и три пути
- `/score`, `/rank` — твои пути и место в стае
- `/invite` — личная ссылка для приглашения (по желанию, `REFERRAL_SECRET`)
- `/change` — платная смена выбора
- `/wallet`, `/stake` — привязка кошелька и постановка ставки Gram (если включены ставки)
- `/top` — копилки и лидеры
- `/fund` — Фонд Стаи: накопление и правила раздачи

Бот запоминает чаты, куда его добавили администратором (группы и каналы), и сам шлёт туда каждый день итоги и новый день. Никаких команд для рассылки не нужно; удаление бота из чата останавливает доставку.

## Команды хранителя (только `ADMIN_IDS`, личные сообщения)

- `/advance` — закрыть день и открыть следующий
- `/resetgame confirm` — полный сброс игры (со счётами/ставками повторить копилки не даёт)
- `/panel` — пульт управления одной кнопкой (день, банк, очередь выплат, watcher, пауза, кассета месяца: выбрать `STORY_CASSETTE_NEXT_KEY` или спрятать сюжетный слой)
- `/pause [причина]` / `/resume` — стоп-кран игры; входящие переводы на паузе автоматически возвращаются
- `/treasury` — здоровье казначея одним сообщением
- `/blockchain` — аудит блокчейн-контура (история казначея, сверка, наши исходящие, stuck)
- `/adjust` — сверка казны с БД и закрытие расхождений
- `/payouts`, `/payout <id> retry|spam`, `/return`, `/fundout`, `/fund`, `/stakes`, `/incoming`, `/revenue` — очередь выплат, журнал входящих и выручка
- `/dispute`, `/disputes` — разбор формальных жалоб на итоги дней

## Наблюдаемость и надёжность

- `/health` — живой снимок: возраст последнего тика планировщика, сердцебиение watcher'а, очередь выплат, мёртвые письма. С `HEALTH_TOKEN` снимок требует авторизации.
- **Аномалии сами находят админа**: watcher не завершает циклы, очередь выплат стоит, появились мёртвые письма — личное сообщение (троттлинг раз в час).
- Сбой обработки апдейта не теряется молча: игрок получает «не получилось», хранителю уходит причина.
- **Self-ping** `/health` раз в `SELF_PING_SECONDS` — free plan Render не засыпает, и день открывается по UTC-сетке.
- **Ежедневный бэкап** в `data/backups/` (04:17 по Москве, хранится 7 копий): SQLite — backup-API, Postgres — `pg_dump`.
- Схема — в моделях (`app/models.py`), история изменений — в `migrations/`. **Единственный источник правды о схеме — Alembic:** на старте рантайм сам приводит базу к `head` (`alembic upgrade head`); свежая база собирается из моделей и штампуется на `head`, легаси-базы create_all-эпохи без alembic-истории конвергируются в таймлайн идемпотентной ревизией `legacy_convergence`. Смена существующих таблиц — `alembic revision --autogenerate` → `alembic upgrade head`; миграции обязаны быть идемпотентно-применимыми. Осиротевшие `NOT NULL`-колонки удалённых механик дропаются только флагом `DROP_ORPHAN_COLUMNS=true` (разовый деплой), иначе — только предупреждение в логах.

## Деплой и миграции

Перед выкатом версии, меняющей схему, прогнать миграции на целевой базе вручную — до старта бота:

```bash
python -m alembic upgrade head
python -m alembic check    # «No new upgrade operations» — модели синхронны с head
```

Для Postgres сделать резервный `pg_dump` перед первым `upgrade head`. В CI те же шаги гоняются на свежей SQLite (джоба «Alembic drift check»).

Что делает старт бота:

- **Свежая база** — схема собирается из моделей (`create_all`), `alembic_version` штампуется на `head`; последующий `upgrade head` — no-op.
- **База, ведущаяся alembic** — `alembic upgrade head` по своему таймлайну.
- **База create_all-эпохи без alembic-истории** — автоматическая реконсиляция: таблицы дотягиваются по моделям, история штампуется на якорь `a7b8c9d0e1f2`, затем база сходится одной идемпотентной ревизией `legacy_convergence`. В логах должно появиться `Легаси-база конвергирована в alembic-таймлайн` — после этого прогнать `alembic check` лишний раз.

Осиротевшие `NOT NULL`-колонки удалённых механик: если в стартовых логах предупреждение `Найдены осиротевшие NOT NULL-колонки` — включи `DROP_ORPHAN_COLUMNS=true` на один деплой (колонки дропнутся, INSERT новых дней перестанет падать) и верни в `false`. Постоянно `true` не держать: при откате версии дроп снесёт колонку, нужную старому коду.
