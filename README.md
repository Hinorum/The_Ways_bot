# Эхо Стаи (The Way)

Фанатская игра по мотивам Lost Dogs: The Way — не связана с официальной командой, использует только общие мотивы и собственные имена. Мир: **Эхо Стаи** — после Последнего Пути стая потерянных собак путешествует по сети нестабильных миров-порталов; каждый мир собран из чужих решений, порталы глючат, а где-то в глубине сети звучит Первый Лай.

Каждый день — три карты. Утром объявляется закон дня: побеждает карта с **большим**, **меньшим** или **средним** числом голосов — сразу понятно, в какую сторону голосовать. Цифры голосов скрыты до итогов. После голосования час уходит на подсчёт. Победивший путь становится каноном, и следующий день ссылается на него.

Платные API не нужны. Картинки по умолчанию берутся с бесплатного Flux через Pollinations. Сюжет пишет «Ведущий» в духе Dungeons & Dragons / Pathfinder: подключи любой бесплатный OpenAI-совместимый LLM (например, токен Hugging Face — `LLM_API_KEY`), иначе бот сам собирает лор из канона «Эха Стаи». Если сеть молчит, карты рисуются локально, а история продолжается без сети.

## Что уже есть

- Один голос на игрока в сутки, без живых лидеров
- Победитель считается одним `GROUP BY` только в час итогов — так можно жить и при миллионе голосов
- Сквозная история: вчерашний След входит в текст и в последствия карт
- **Тихие последствия**: каждый путь оставляет неназванный след — он может всплыть в сюжете через несколько дней, а может раствориться; бот ничего не подсвечивает и не оповещает, заметит повтор только внимательный игрок
- **Кнопка «Я помню этот след»** под постом дня: заметил повтор давнего дня — нажми. Бот не подтверждает догадку, но копит счётчик «Память сети» в `/score`. Визуальные приметы эхов попадают и в картинки дня (предмет из давнего мира в кадре).
- **Автопилот истории**: нейросеть пишет главу дня (1800–2600 знаков: сцена с репликой персонажа, закон дня голосом Архивариуса, крючок перед картами) вместе с тремя путями — у каждого обещание и угроза — и их последствиями; по английским промптам рисуются картинки, победивший путь становится предысторией завтрашней главы, а эпилог закрывает день недоговорённым крючком
- **Полные описания путей в подписях карт**: каждая картинка пути несёт своё описание (до 700 знаков) прямо в подписи фото — развилка читается не отрываясь от истории
- **«Канон на волоске»**: в итогах дня появляется строка, сколько голосов отделяло мир от другого исхода («ещё 2 голоса за путь II — и тропа повела бы иначе»)
- **Личное эхо проигравшим** (`PERSONAL_ECHO`): после итогов каждый, кто голосовал мимо победителя, получает в личку короткое «чем пахла бы его тропа» и мостик к новой развилке
- Обложка дня: широкая картинка с завязкой сюжета перед тремя картами выбора
- Картинка на каждый путь
- SQLite из коробки, без облака и без Docker
- Мир настраивается переменными `WORLD_NAME` и `WORLD_BRIEF`: сменишь их в Environment — получишь другой сеттинг с той же механикой
- На Render работает через webhook (`/health`, `/webhook`) и Postgres

- Имя (`/setname`): **The Ways** — короткое имя чище длинных названий мира.
- Аватар (`/setuserpic`): гудящий портал на туманной окраине, силуэты потерянных псов, бирюзово-фиолетовое свечение, без текста.
- Картинка описания (`/setdescriptionpic`): тот же кадр шире — стая перед развилкой из трёх порталов.

## Как устроен день

Сутки Стаи всегда одинаковые и заякорены на сетку UTC (`DAY_OPEN_HOUR_UTC`, по умолчанию 11:00):

1. **Открытие дня — 11:00 UTC** — гудок портала, глава истории, три карты. Итоги предыдущего дня выходят здесь же, сразу после подсчёта.
2. **23 часа (11:00 → 10:00 UTC)** — выбор одной из трёх карт. Закон дня объявлен утром, счётчики голосов не отдаются ни игрокам, ни боту в чат. Дедлайн виден в статусе дня: «Голосование до: 10:00 UTC».
3. **10:00 → 11:00 UTC** — голосование закрыто, час подсчёта: один SQL-агрегат, начисление очков, запись Следа в канон. Вскоре после закрытия во все чаты уходит **тизер ожидания** — пара строк недосказанности от Архивариуса: выбор сделан, но счёт ещё не называется.
4. **Итоги — сразу после подсчёта (11:00 UTC)** — фото победившего пути и **театр вскрытия урны**: реплика о том, как закон дня сыграл против голосов (включая парадоксы «стая проголосовала против закона»), расклад цифр, банк дня и число игравших, коэффициент верного пути, взнос в копилки недели и месяца, эпилог с крючком на завтра — и сразу новый день.

Первый день (после деплоя или `/resetgame confirm`) стартует сразу и закрывается на ближайшей сетке; дальше дни идут строго по расписанию даже после простоя бота.

## Сезон: арка забега от сброса до Первого Лая

Арка привязана к **забегу** (периоду от `/resetgame` до следующего сброса),
а не к календарю: якорь старта живёт в `watcher_state`, акт 1 всегда начинается
со дня 1 забега, а День Первого Лая наступает, когда забег дорастает до длины
месяца своего старта (длинные забеги циклятся — нарратив перезапускается,
экономика не трогается). Копилки недели/месяца остаются календарными.
Экономика дня при этом не меняется: закон, голосование и ставки живут как раньше.

Акты забега: первые дни — тихие странности; середина — Лай слышится чаще;
последние семь дней — кризис, порталы дрожат. **Последний день забега — День
Первого Лая**: три карты суть три его прочтения (дом / ловушка / стать зовом),
и флейвор финала зависит от накопленного характера стаи — баланса
риск/забота/хитрость по победившим путям. Эпилог финального дня закрывает сезон.

Полный сброс начинает новый забег: якорь обнуляется, акты стартуют с акта 1,
план Хозяина Ошибки пересобирается с другой солью событий. `keepstory` тоже
начинает новую арку, но мир помнит канон прошлого забега.

1-го числа, сразу после распределения копилки лидеров, начинается новый сезон:
счёты игроков продолжаются, но мир помнит прошлый финал как осадок — первый
день нового сезона показывает, чем пахнет утро после Лая. Статус дня показывает
акт сезона и дистанцию до Лая; вечером (час настраивается `WHISPER_HOUR_UTC`,
по умолчанию 16:00 UTC = 19:00 Москвы) приходит «вечерний привал» — микросцена,
продолжающая утреннюю главу одной репликой и недоговорённостью перед закрытием
развилки.

Следующий день готовится заранее в две фазы: в час подсчёта бот в фоне собирает главу (без отголоска — итог дня ещё не вскрыт), визуальную библию и четыре картинки в заготовку (`PreparedDay`); сразу после вскрытия итогов отдельный короткий вызов дописывает открывающий абзац-отголосок прямо в заготовку (`patch_prepared_day`). Поэтому в 11:00 UTC новый день открывается мгновенно, и его утро честно отзывает только что сделанный выбор. Заготовка не удалась или битая — день откроется обычным синхронным путём, мягкая деградация без ручного вмешательства.

### План Хозяина Ошибки

У сезона есть сквозной сюжет: антагонист мира действует по плану из четырёх
ступеней, привязанных к актам месяца (приметы → первое вмешательство →
послания стае → его ход в кризисе). Каждая ступень при наступлении оставляет
одно каноническое событие — детерминированный выбор из пула по ключу сезона,
состояние живёт в `watcher_state` и переживает рестарты. Глава получает блок
«уже случившегося» и вплетает его одним касанием; полный `/resetgame`
начинает новый план, `keepstory` сохраняет старый.

### Глухой день

Раз в `SEALED_DAY_EVERY` дней (по умолчанию 10) закон дня не объявляется
утром: игроки видят только хеш-обязательство Архивариуса, а сам закон
вскрывается в итогах вместе со счётом («Запечатанный с утра закон оказался…»).
Глава глухого дня нагнетает двойную интригу — персонажи спорят и гадают,
Архивариус молчит с ухмылкой; тизер в час подсчёта добавляет вторую строку
ожидания. Механика честности не меняется: хеш по-прежнему не даёт подменить
закон после голосов.

Личная нить игрока: `/score` показывает хронику последних дней сезона —
какой путь ты выбирал и чем он кончился (🏆 — верный).

Админ-команда **`/resetgame`** имеет два режима:

- `/resetgame confirm` — полный сброс: стирает дни, голоса, ставки, выплаты, очки и весь канон истории, запускает день 1 с чистого листа.
- `/resetgame confirm keepstory` — «разделить команды»: счёты, голоса, ставки и выплаты обнуляются, но канон истории и эхо прошлого сохраняются — новый день 1 продолжает тот же мир с памятью о былых решениях.

В обоих режимах кошельки игроков, привязки чатов и копилка месяца не трогаются.

На старте дня закон (больше / меньше / среднее) уже выбран и захеширован: хеш-подпись не даёт подменить его после того, как игроки проголосовали.

## Масштаб

Голос — это `INSERT` с уникальностью `(round_id, player_id)`, без обновления общего счётчика. Подсчёт — `COUNT(*) GROUP BY card_position`. Для миллиона игроков позже достаточно вынести `votes` в Postgres и партиции по дню; логика не меняется.

## Память мира и стиль

- **Дальняя память** (`app/memory.py`): все дни старше окна канона превращаются в хэш-векторы символьных триграмм (чистая математика на crc32 — детерминированно между перезапусками, без нейросетей и внешних API). Перед генерацией дня мир вспоминает 2–3 сюжетно близких давних дня и вплетает их в главу лёгким касанием: история остаётся связной на горизонте недель, а не двенадцати дней.
- **Преемственность стиля**: якорь предыдущего дня (палитра, свет, сквозные мотивы) передаётся арт-директору следующего и живёт в `watcher_state`, так что визуальный ряд не «прыгает» ото дня ко дню. Сквозные персонажи (Лайнер, Архивариус, Хозяин Ошибки) получают стабильные визуальные дескрипторы, когда упомянуты в главе, — фигуры узнаваемы изо дня в день; сид обложки привязан к названию места дня (`place_seed_for`), поэтому возвращение стаи в «Старый приют» выглядит как возвращение. Офлайн-PIL фолбэк рисует многослойный пейзаж с туманом и силуэтами идущей стаи, а не шаблонную заглушку.

## Наблюдаемость и эксплуатация

- `/health` отдаёт живые метрики JSON'ом: возраст последнего тика планировщика (если тиков нет дольше 5 минут — админу уходит алерт: молчаливая смерть расписания раньше была невидима), возраст последнего успешного цикла TON-watcher'а (`watcher_beat_age`; сердцебиение ставится каждым циклом с живым TonAPI — даже если переводов не было), размер очереди выплат и возраст старейшей выплаты, число мёртвых писем.
- Сбой обработки апдейта (кнопка/команда) не теряется молча: игрок получает честное «не получилось», кнопке снимается спиннер, а хранителю в личку раз в час уходит причина (тип исключения и краткое описание; полный стек — в логах по строке «Ошибка обработки апдейта»). `/today` доставляет текст дня с кнопками, даже если медиа-группа картинок не ушла.
- Аномалии сами находят админа: watcher больше 30 минут не завершает успешных циклов (TonAPI лежит или процесс завис), очередь выплат стоит на месте или появились мёртвые письма — личное сообщение (троттлинг раз в час, чтобы не заваливать чат). Тишина в блокчейне тревогой не считается: курсор двигается только переводами, поэтому за «жизнь» watcher'а отвечает отдельное сердцебиение.
- Ежедневный бэкап в `data/backups/` (крон 04:17 UTC, хранятся 7 копий): SQLite — штатный backup-API, Postgres — `pg_dump`, если утилита есть в окружении (иначе пропуск с предупреждением; включите снапшоты провайдера).
- Self-ping: сервис сам пингует `/health` раз в `SELF_PING_SECONDS` (по умолчанию 600) — free plan Render не засыпает, и день открывается по UTC-сетке.
- `/revenue` (только админам) — выручка Stars и TON за текущий месяц и за всё время из единого журнала доходов; каждая звезда и каждый перевод записываются с idempotency-ключом (`charge_id`/хэш транзакции).

## Миграции схемы (Alembic)

Схема живёт в моделях (`app/models.py`), история изменений — в `migrations/versions/`. Рантайм по-прежнему сам поднимает свежую базу (`init_db` → `create_all`), так что новый инстанс или тесты работают без шагов вручную; Alembic нужен, когда меняются **существующие** таблицы.

- Поменяли модель: `alembic revision --autogenerate -m "суть изменения"` → просмотрите сгенерированный файл → `alembic upgrade head` локально → коммит вместе с моделью.
- Существующее производство (база уже создана до внедрения Alembic): один раз пометить как актуальную — `alembic stamp head`, после чего обычные `upgrade head` при деплое.
- Baseline-миграция проверена на паритет: схема после `alembic upgrade head` идентична `create_all` (таблицы, колонки, индексы); `alembic check` подтверждает отсутствие дрейфа моделей.

## TON-ставки (каркас, выключено)

Игра остаётся бесплатной: ставки — отдельный слой, который включается флагом `TON_ENABLED=true`.

> **О названии валюты.** Монета сети теперь называется **Gram** (ранее — TON). В сообщениях для игроков бот пишет «Gram»; в настройках и коде она по-прежнему фигурирует под техническим именем TON (`TON_ENABLED`, `STAKE_MIN_TON`, TonAPI) — переименование этих идентификаторов сломало бы деплой и ничего не дало бы игрокам. Речь везде об одной и той же монете.

- `/wallet` — игрок привязывает Gram-кошелёк (один кошелёк = один игрок). Два способа: `/wallet <адрес>` одной командой или просто `/wallet` — бот попросит адрес следующим сообщением и привяжет сам (отмена — словом «отмена»). Пока ставка в незакрытом дне, кошелёк закреплён — так выплату нельзя угнать перепривязкой.
- Ставка — перевод на казначейский кошелёк в течение дня. Порядок не важен: голос кнопкой и перевод можно заносить в любой последовательности, обе части должны успеть до закрытия голосования. `/stake` в личке показывает адрес казначея, шаги и статус своей ставки. Watcher (`app/ton_watch.py`) раз в минуту читает входящие транзакции через TonAPI и сопоставляет отправителя с привязанным кошельком. Если TonAPI деградировал (404 истории при живом казначее или полный аутейдж), тот же проход автоматически повторяется через Toncenter v3 — источник последнего успешного цикла виден в `/health` как `watcher_source`. Позиция прочитанных транзакций хранится в базе (`watcher_state`): простой сервиса не теряет переводы, а страницы API проходятся вглубь (`WATCH_MAX_PAGES` × `WATCH_PAGE_LIMIT`, по умолчанию до 5000 транзакций за цикл), пока не накроют курсор или не кончится история; подряд идущие страницы без новых переводов завершают проход досрочно. Покрытие кумулятивно: после лавины переводов хвост догоняется за несколько минут, деньги в казнее не теряются в любом случае — непринудимый перевод либо становится ставкой позже, либо возвращается отправителю автоматически.
- Одна ставка на игрока в день, нижняя граница `STAKE_MIN_TON`, верхней нет, идемпотентность по хешу транзакции. Переводы, которые не могут стать ставкой (непривязанный кошелёк, повтор за уже поставившего, закрытый день, слишком мелкая оплата смены пути), автоматически попадают в очередь возвратов — деньги не оседают в казнее молча. Авто-возврат создаётся только свежим переводам (младше `WATCH_REFUND_MAX_AGE_DAYS`, по умолчанию 14): после сброса базы курсор обнуляется и история казни перечитывается заново, но старый спам-хлам больше не рожает новые dead-letter возвраты.
- **Ставкой является только нативная монета сети — Gram (ex-TON).** Перевод токена (USDt, NOT, любой другой джеттон) фонд не пополняет и не смешивает с ним: watcher узнаёт jetton-уведомление (`0x7362d09c` / `transfer_notification`) и пропускает его целиком — без ставки и без пыльного авто-возврата обёртки. Токены просто лежат на балансе казначея; вернуть их отправителю можно только вручную. Пополняйте счёт игры исключительно Gram (бывший TON).
- Ставка **не** меняет вес голоса. После итогов дня фонд делится по правилам из раздела «Экономика дня» ниже; если на победивший путь не поставлено — все ставки возвращаются целиком.
- Выплаты (`app/ton_pay.py`) отправляются через pytoniq напрямую лайтсерверам активной сети. Казначейский кошелёк может быть как v4r2, так и v5r1 (современные кошельки): версия определяется автоматически по адресу казначея или задаётся `TREASURY_WALLET_VERSION=v4r2|v5r1`. Несовместимая пара мнемоника/адрес отсекается до выхода в сеть. Версия pytoniq-core запинена (0.1.46): более новый 0.2.0 молча ломает сборку переводов. Выплата проходит путь `pending → sending → sent/failed`: статус «взята в работу» фиксируется до вещания, поэтому падение сервиса не приводит к двойной оплате. Неуспешные выплаты ретраятся автоматически (`PAYOUT_MAX_ATTEMPTS`), о зависших админ получает сообщение в личку. В поле `tx_hash` хранится метка вещания — фактический перевод ищется в эксплорере по memo вида `way:<день>:<тип>#<id>`.
- **Ручной разбор** (только админам, в личке): `/payouts` — список неотправленного с причиной последней неудачи у каждой строки (`last_error`: не совпала мнемоника/адрес, лайтсерверы отвергли перевод, нет `OWNER_WALLET_ADDRESS`, TON выключен…); `/payout <id> spam` — пометить спамом (пыльная атака с рекламой: выплата уходит из очереди, алертов и перестаёт блокировать `/resetgame`); `/payout <id> retry` — вернуть настоящий долг в очередь с нуля. Доля казны (рейк/копилка месяца), созданная до появления `OWNER_WALLET_ADDRESS`, оживает сама при следующем цикле диспетчера — адрес подставляется из окружения перед отправкой.
- **`/treasury`** (только админам, в личке): здоровье казначея одним сообщением — адрес, мнемоника, баланс через TonAPI→Toncenter, сверка пары мнемоника/адрес (v4r2/v5r1, детект по адресу) и состояние очереди выплат. Инцидент «выплаты не уходят» разбирается без логов и без раскрытия мнемоники.
- **Анти-дубль перед повтором**: если краш/таймаут случился сразу после вещания перевода, ретрай сначала сверяется с memo недавних исходящих казначея (`way:<день>:<тип>#<id>`); найденный перевод помечается sent без новой отправки — задвоение платежа исключается.
- **«have no alive peers»**: встроенный конфиг тестнет-лайтсерверов pytoniq периодически мёртв, а из части облачных окружений UDP закрыт — исходящие переводы встают с этой причиной в `/payouts`. Лечение: `LITESERVER_CONFIG_URL=https://ton.org/testnet-global.config.json` (свежий конфиг), либо запуск бота **локально** на той же `DATABASE_URL` на несколько минут — диспетчер разошлёт очередь из домашней сети, после чего локальный процесс можно остановить.
- **Картинки против 429**: `POLLINATIONS_TOKEN` поднимает лимиты анонимного tier'а; ответ 429 ставит общий предохранитель (остальные кадры дня сразу уходят в PIL-заглушки без выжигания лимита), а через 15 минут после анонса фоновая задача перерисовывает заглушки нейромоделью — `/today` показывает уже полноценные кадры.
- **`watcher_state` без потолка**: план Хозяина Ошибки и другие служебные состояния живут в TEXT — раньше план на 2-й ступени сезона переставал влезать в VARCHAR(255) и ронял тик до создания следующего дня.
- **Видимость ставки для игрока**: `/stake` в личке и `/wallet` показывают «Ставка сегодня: X Gram» со статусом; кнопка «Как поставить» в группах показывает ту же сумму в приватном попапе.
- Копилка месяца выплачивается автоматически 1-го числа: сумма всех прошедших месяцев уходит лидеру (лидерам при ничьей — поровну) по числу верных путей. Лидер без `/wallet` не блокирует выплату остальным — его доля делится между оплативаемыми, а месяц остаётся «незакрытым» до следующего удачного цикла.
- Копилка недели выплачивается автоматически в понедельник топ-3 недели (20/30/50% местам, допуск — кошелёк и 4+ дня голосования; незаполненные места переносятся) — см. «Копилка недели» ниже.

### Экономика дня

1. Фонд дня = сумма всех подтверждённых ставок (лимит 0.1–10 TON на игрока).
2. Если среди победителей есть поставившие, фонд делится так:
   - **97%** — выбравшим победивший путь и поставившим, пропорционально ставкам;
   - **2%** — в копилку недели (`WEEKLY_POT_PCT`): в понедельник её делят топ-3
     недели по числу верных путей — 20% / 30% / 50% местам (`WEEKLY_PRIZE_PCTS`);
   - **0,5%** — хранителю игры (`OWNER_RAKE_PCT`);
   - **0,5%** — в копилку месяца (`LEADERBOARD_RAKE_PCT`): в конце месяца её забирает игрок (игроки) с максимумом верных путей — таблица `/top`.
3. Если на победивший путь не поставил никто — все ставки возвращаются 100%, рейка и копилок нет.
4. Отклонённые лимитами и неподтверждённые ставки возвращаются всегда.
5. Пример: фонд 10 TON → 9.7 TON ставившим за верный путь пропорционально, 0.2 TON в копилку недели, 0.05 TON копилка месяца, 0.05 TON хранителю.
6. **Смена выбора — платно**: сутки на раздумья, но передумать можно за ⭐25 Stars или от 0.1 TON с memo `rv:<день>` (`/change` в личке). Грант действует до закрытия дня и сгорает вместе с ним (возврат — вручную по обращению). Автоматический возврат звёзд через Telegram отзывает неиспользованный грант и алертит хранителя, если грант уже потрачен.

### Копилка недели

Каждый день 2% фонда капает в копилку недели. В понедельник сумма уходит
топ-3 прошедшей недели по числу верных ответов: место 1 — 20%, место 2 —
30%, место 3 — 50%. Ничьи решаются детерминированно: верные пути → дни
участия → меньший id. Чтобы претендовать на призовое место, нужно два
условия: привязанный кошелёк (`/wallet`) и минимум `WEEKLY_MIN_DAYS` дней
голосования за неделю (по умолчанию 4) — иначе фермы мультиаккаунтов
собирали бы приз дешёвыми голосами. Доля места без достойного игрока не
пропадает: она переносится в копилку новой недели. Неделя дня считается
по моменту открытия дня, выплата проходит сразу после финализации
последнего дня недели; живая таблица — в `/top`, церемония приходит во все
чаты утром понедельника.

Бот и хранитель не отвечают за утраченные средства по любой причине: ошибки игрока, сбои сетей, блокчейна, API или хостинга. Ты сам решаешь, на что ставить, и сам отвечаешь за свои ставки. Ставь только то, что готов потерять. DYOR.

Известный технический предел: один Telegram-аккаунт = один игрок, но человек может завести несколько аккаунтов. Ставки делают такой фрод дорогим (каждый голос подкреплён своими деньгами), однако полностью он не лечится никаким кодом. И помни: игра с реальными ставками в ряде юрисдикций регулируется как азартная — ответственность за соответствие местным законам лежит на хранителе, дисклеймер юридической защитой не является.

### Безопасность

- Токен бота, мнемоника казначея и `WEBHOOK_SECRET` живут только в Environment (Render/локальный `.env`) — в git не попадают.
- `/advance` и `/resetgame` принимаются только от админов из `ADMIN_IDS`; служебное меню команд их не показывает.
- Один кошелёк = один игрок, одна ставка и один голос на игрока в день закреплены уникальными индексами в БД; перепривязка кошелька заблокирована, пока ставка в игре.
- Сброс игры (`/resetgame confirm`) невозможен, пока в очереди есть хоть одна неотправленная выплата — обнуление не может стереть денежные обязательства казны; сначала дайте автоплатежам уйти или разберите зависшие вручную.
- Адреса кошельков хранятся в каноническом raw-виде (`0:…`): watcher сопоставляет отправителя транзакции независимо от того, в какой форме (UQ/EQ) игрок прислал адрес; старые привязки мигрируют автоматически при первом цикле наблюдателя.
- Заготовка антисибила — `wallet_trust()` в `app/ton_utils.py`: при включении ставок сюда ложится оценка возраста и активности кошелька через TonAPI (свежий пустой кошелёк → пониженный лимит или ручная проверка).
- Генерации нейросети проходят грубый стоп-фильтр (`CONTENT_FILTER`, `app/story.py`) перед постингом в чаты.
- Картинки дня рисует цепочка «арт-директор» (`app/art_director.py`): отдельный запрос к нейромодели собирает визуальную библию дня (палитра, свет, сквозные мотивы и четыре разных кадра — обложка и три пути под смысл каждого выбора), затем чистая функция-промпт-инженер собирает финальные промпты с анти-текст негативами, а генерация идёт по лестнице моделей Pollinations (flux → sana → turbo) с повторной попыткой сжатым промптом. Если сеть молчит совсем — локальный абстрактный арт без текста (PIL), поэтому стиль дня никогда не рассыпается на «шаблоны с надписями».
- Выплаты фиксируют статус «взята в работу» до вещания в блокчейн — падение сервиса не приводит к двойной оплате; исчерпавшие ретраи выплаты будоражат админа личным сообщением.

Распределение фонда показано игрокам в `/start` и `/wallet`, копилки недели и месяца с лидерами — в `/top`.

### Тестнет как второй контур

`TON_NETWORK=testnet` переключает весь контур на тестнет: свой казначей (`TREASURY_TESTNET_ADDRESS/MNEMONIC`, кошелёк можно пополнить через @testgiver_ton_bot), свой TonAPI (`testnet.tonapi.io`). Ставки и выплаты помечены колонкой `network` и не смешиваются с mainnet: финализация и watcher работают только со ставками активной сети. Реальные деньги не включай, пока не прогонишь весь цикл на тестнете.

## GitHub и Render

Токен бота в git не кладётся. На Render он живёт в Environment.

1. Запушь этот код в свой GitHub-репозиторий (`git push` — см. историю коммитов).
2. Бесплатная Postgres: [Neon](https://neon.tech) → скопировать connection string.
3. [Render](https://render.com) → New → Blueprint, указать этот репозиторий и `render.yaml`.
   Либо New Web Service: runtime Python, build `pip install -r requirements.txt`, start `python -m app.main`, health check `/health`.
4. Environment:

```
BOT_TOKEN=токен от @BotFather
ADMIN_IDS=твой числовой Telegram id
DATABASE_URL=postgres://...из Neon
PYTHON_VERSION=3.12.8
WEBHOOK_SECRET=любая случайная строка
```

Без `PYTHON_VERSION` Render берёт Python 3.14, и сборка `pydantic-core` падает.

`PORT` и `RENDER_EXTERNAL_URL` Render подставляет сам — по ним бот ставит webhook.

5. После деплоя открой `https://<сервис>.onrender.com/health` — должно быть `ok`. Затем `/start` у [@the_ways_bot](https://t.me/the_ways_bot).

Бесплатный веб-сервис Render засыпает без трафика. Чтобы сутки голосования не обрывались, пингуй `/health` раз в 10 минут (UptimeRobot бесплатно) или возьми план Starter.
