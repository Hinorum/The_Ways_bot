## 2. 🔴 HIGH — подтверждённые баги (все исправлены)

### 2.1 Квиз памяти никогда не отвечался верно → мертво призвание «Архивариус»
- **Файл:** `app/handlers.py:590-594` + `app/echoes.py:142-145`.
- **Суть:** `build_memory_quiz` возвращает `"correct": set(correct_indices)` —
  множество **индексов (int)**. Хендлер сверял `quiz["options"][index] in
  quiz["correct"]` — **строку** (текст варианта) с множеством int → всегда
  `False`. Реальный игровой путь не давал правильного ответа никогда.
- **Каскад:** `register_memory_hit` (`handlers.py:597`) не срабатывал →
  ни одного `MemoryHit` → призвание **Архивариус** (`memory_hits >= 3`,
  `callings.py:70,127-131`) — вечное «???»; номинация «Самый памятливый пёс
  недели» (`leaderboard.py`) и награда «+1 нюх» недостижимы.
- **Почему не ловилось:** старые тесты вставляли `MemoryHit` напрямую, минуя
  игровой путь.
- **Фикс:** добавил `correct_memory_choice(quiz, index) -> bool`
  (`echoes.py`) — сверяет именно индекс; хендлер зовёт её.
- **Тест:** `tests/test_memory_quiz.py::test_correct_memory_choice_uses_index_not_text`.

### 2.2 Гонка «тик ↔ финализация дня» → «двойной день» (прыжок вперёд)
- **Файлы:** `app/scheduler.py:410,501,566` и `app/rounds.py:1208-1267,1361`.
- **Суть:** бесшовное закрытие дня N (`scheduler.py:454-457`) спавнит
  `_finalize_new_day_job(N)` (эпилог-LLM → секунды), а следующий тик (+15 c)
  через `ensure_current_round` сам создаёт N+1 и анонсит его. Когда финализация
  доходит до `create_next_round_detailed`, она считает
  `next_day = latest.day_index + 1` **динамически** — видит уже созданный N+1 и
  открывает **N+2**, анонсируя его → прыжок на сутки вперёд, потерянные итоги
  N+1 (закрывается `heal_stale_rounds` без рассылки). `unique(day_index)`
  спасает от дубликата дня, но не от эскалации в N+2. При 2 процессах — ~100%.
- **Фикс:** `create_next_round_detailed(session, base_day_index=None)` теперь
  умеет открывать **ровно** `base_day_index + 1` (а не `latest + 1`) и рано
  возвращает уже существующий целевой день. `_finalize_new_day_job` передаёт
  `base_day_index=finished_day_index`.
- **Тест:** `tests/test_polish.py::test_create_next_round_base_day_index_does_not_escalate`.

## 3. 🟠 MED — структурные дыры (исправлены)

### 3.1 Деньги: revote-memo не проверял верхнюю границу ставки
- **Файл:** `app/ton_watch.py:705-718,521-525`.
- **Суть:** авто-грант по сумме ограничен вилкой `[revote_ton, stake_min_ton)`,
  а «мемо»-путь `_process_revote` проверял только нижнюю границу. «Ставкоподобный»
  перевод (≥ `stake_min_ton`) с `rv:`-мемо тихо списывался как дешёвая смена пути,
  весь его баланс уходил в `Income` без записи ставки.
- **Фикс:** добавлен симметричный верхний порог → новый статус
  `revote_too_large` → возврат с объяснением.

### 3.2 Деньги: дубликат привязки кошелька — необработанный IntegrityError
- **Файл:** `app/handlers.py:850-920` (модель `unique=wallet_address`,
  `models.py:61`).
- **Суть:** привязка адреса, уже закреплённого за другим игроком, падала на
  `IntegrityError` при `commit` → «краш» хендлера.
- **Фикс:** предпроверка дубля + перехват `IntegrityError` с вежливым ответом.
- **Тест:** `tests/test_wallet_flow.py::test_duplicate_wallet_bind_is_rejected_not_crash`.

### 3.3 Деньги: `_migrate_wallet_formats` падал на дублях нормализованных raw
- **Файл:** `app/ton_watch.py:912-955`.
- **Суть:** легаси-привязки одного кошелька в UQ/EQ…-формах нормализуются в один
  raw и нарушали `unique=wallet_address` на `commit` → миграция валилась каждый
  тик watcher'а.
- **Фикс:** детерминированное разрешение дублей — один raw закрепляется за одним
  владельцем (канонический держатель либо меньший id), остальные пропускаются
  с предупреждением.
- **Тест:** `tests/test_ton.py::test_wallet_migration_survives_duplicate_raw`.

### 3.4 ARG: страницы Совета №5–6 недостижимы в месячном забеге
- **Файл:** `app/council.py:55-67` (`COUNCIL_DAY_MODULO = 7`).
- **Суть:** 6 страниц при шаге 7 дней требовали дня 42; месячный забег
  (28–31 день, февраль — 28) давал только дни 7/14/21/28 → страницы №5 и
  манифест Еретика (№6) никогда не попадались.
- **Фикс:** шаг 4 дня → последняя страница на дне 24, все 6 достижимы даже в
  28-дневном феврале.
- **Тесты:** `tests/test_story_canon.py::test_council_pages_cadence_and_rotation`
  (обновлён) + `test_council_all_pages_reachable_in_short_run` (новый).
